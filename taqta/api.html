API модуля «Игры для урока»

Черновик контракта, на котором работает демо (в демо сервер имитируется в браузере). Это стартовая точка для согласования на первой неделе: имена полей, коды ошибок и путь подстраиваются под правила платформы.

Общие правила

  • Базовый путь: /api/v1/lesson-games. JSON, UTF-8, даты — ISO 8601 в UTC, идентификаторы — UUID.
  • Авторизация — существующая схема платформы (например, Authorization: Bearer <токен>). Владелец игры берётся из токена, а не из тела запроса. Своей регистрации у модуля нет.
  • Чужая игра → 403, несуществующая → 404, истёкший токен → 401 (фронтенд показывает повторный вход и не теряет форму).
  • Защита от перезаписи: PUT принимает заголовок If-Match: <version>; если игру уже поменяли в другой вкладке — 409.
  • Тексты заданий хранятся как ввёл учитель, без нормализации (казахские буквы, кавычки, тире).

  "id": "6e8611d1-8957-4274-8490-9c6d8c88cb34",
  "title": "Природа Казахстана",
  "format": "true_false",            // true_false | fill_gap | matching
  "language": "ru",                  // kk | ru
  "status": "ready",                 // draft | ready
  "version": 3,
  "createdAt": "2026-11-14T06:57:10Z",
  "updatedAt": "2026-11-14T07:02:44Z",
  "tasks": [ ... ]                   // порядок в массиве = порядок показа
}

Задания трёх форматов

// «Правда или ложь»
{ "id": "…", "type": "true_false", "statement": "Иртыш впадает в Каспийское море.", "answer": false }

// «Заполни пропуск»: ровно один маркер ___ и правильный ответ
{ "id": "…", "type": "fill_gap", "text": "Единица измерения силы — ___.", "answer": "ньютон" }

// «Найди соответствие»: от 2 до 6 пар, подсказка необязательна
{ "id": "…", "type": "matching", "prompt": "Страна — столица",
  "pairs": [ { "id": "…", "left": "Казахстан", "right": "Астана" },
             { "id": "…", "left": "Кыргызстан", "right": "Бишкек" } ] }

Правила проверки (одинаковые на фронте и на сервере)

  • Название обязательно, до 120 символов. Заданий от 1 до 50, все — формата игры. Формат после создания не меняется.
  • «Правда или ложь»: утверждение до 300 символов, ответ true или false.
  • «Заполни пропуск»: текст до 300 символов, ровно один ___, ответ не пустой.
  • «Найди соответствие»: 2–6 пар, каждая половина до 80 символов, без повторов в столбце.

Ошибки

HTTP/1.1 422 Unprocessable Entity
{
  "error": {
    "code": "validation_failed",
    "message": "Validation failed",
    "fields": {
      "title": { "key": "v.required" },
      "byTask": { "b1c…": { "gap": { "key": "v.pickGap" } } }
    }
  }
}

Коды: unauthorized (401), forbidden (403), not_found (404), version_conflict (409), validation_failed (422). В fields — ключи сообщений, тексты на kk/ru берёт фронтенд.

Хранение (PostgreSQL)

lesson_games (
  id uuid pk, owner_id text not null, title text not null,
  format text not null, language text not null, status text not null,
  version int not null default 1,
  created_at timestamptz not null, updated_at timestamptz not null, deleted_at timestamptz null
)  index (owner_id, updated_at desc) where deleted_at is null

lesson_game_tasks (
  id uuid pk, game_id uuid fk → lesson_games on delete cascade,
  position int not null, type text not null, payload jsonb not null,
  unique (game_id, position)
)

PUT заменяет задания игры целиком в одной транзакции — так порядок всегда совпадает с тем, что прислал клиент. Миграции — инструментом, принятым у заказчика.

Аналитика (фронтенд)

Пять событий: format_selected, game_first_saved, show_started, answer_revealed, show_finished. Передаются только id игры, формат, номер задания и технические параметры. Тексты заданий и ответов в аналитику не уходят.

Демо: gamemetric.dev/taqta/. Кнопка «Проверка» в правом нижнем углу включает сбои API (обрыв сети, 401, ошибку загрузки) и показывает события аналитики.
